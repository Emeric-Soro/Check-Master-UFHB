8. DUPLICATION — Pattern CRUD dans les modèles
================================================================================

26 modèles sur 48 suivent le même pattern CRUD de base :
  - ajouterXXX / createXXX
  - updateXXX / modifierXXX
  - deleteXXX / supprimerXXX
  - getXXXById / getByXXX

Modèles concernés :
  Action, AnneeAcademique, Attribution, CritereEvaluation, Echeance,
  Enseignant, Entreprise, Etudiant, Fonction, Grade, GroupeUtilisateur,

  Specialite, StatutJury, Traitement, TypeUtilisateur

Chaque modèle réimplémente ses propres requêtes SQL pour ces opérations
de base, alors que le schéma est toujours le même :
  - ajouter : INSERT INTO table (colonnes) VALUES (?, ?, ...)
  - update  : UPDATE table SET colonne=?, ... WHERE id=?
  - delete  : DELETE FROM table WHERE id=?
  - getById : SELECT * FROM table WHERE id=?

8a. Getters/Setters manuels (modèles Enseignant, PersAdmin, Fonction, Specialite)

Ces modèles définissent manuellement des getters/setters pour chaque 
propriété, ce qui est redondant avec PHP (propriétés publiques ou 
méthodes magiques __get/__set pourraient être utilisés).

  Enseignant.php  : 15 getters/setters (getIdEnseignant, setNomEnseignant, etc.)
  PersAdmin.php   : 14 getters/setters
  Fonction.php    : 4 getters/setters
  Specialite.php  : 4 getters/setters

La logique est toujours : return $this->propriete;

SOLUTION RECOMMENDÉE : BaseModel abstraite avec CRUD générique utilisant 
des métadonnées de table + générateur de requêtes.

11. DUPLICATION — Constructeurs de contrôleurs
================================================================================

Pattern très répété : 
    public function __construct()
    {
        $db = Database::getConnection();
        $this->service = new NomService($db);
    }

Mais avec beaucoup de variations inutiles :
  - Certains reçoivent $db en paramètre : __construct($db = null)
  - Certains utilisent une injection : __construct($pdo)
  - D'autres initialisent des modèles supplémentaires : new AnneeAcademique($this->db)

Les incohérences dans les signatures (null par défaut, type-hint, appel direct)
sont un signe supplémentaire de duplication non maîtrisée.

12. DUPLICATION — Fichiers utils
================================================================================

12a. RecuDataUtils.php (317 lignes, 11 fonctions) vs ReceiptUtils.php (146 lignes, 4 fonctions)

Ces deux fichiers dans app/utils/ traitent des reçus mais ont des 
approches différentes :
  - ReceiptUtils : statique, utilitaires de calcul (nombre en lettres, dates)
  - RecuDataUtils : basé sur Database, persistance des données de reçu
  
La fonction `intToWords` (RecuDataUtils) et `numberToWords` (ReceiptUtils) 
font la même chose — conversion d'un nombre en lettres — mais avec des 
implémentations différentes. Fonctionnellement ce sont des duplicatas.

12b. PlanningDataUtils.php (1059 lignes) — Utilitaire surdimensionné

Contient ses propres méthodes tableExists() et columnExists() alors qu'il 
y a déjà 32 et 22 duplicatas respectivement.

12c. ComponentHelper.php (2719 lignes, 135 fonctions) — Méga-fichier

Le plus gros fichier de la codebase. Mélange de rendu HTML, helpers de 
composants, et fonctions utilitaires disparates. Son nom "Helper" cache 
une accumulation de responsabilités.
