# PLAN DE REFACTORISATION COMPLET - CHECKMASTER

Ce document détaille le plan de refactorisation des 76 fichiers de vues identifiés dans `ressources/views/`. L'objectif est de supprimer Tailwind CSS et les styles inline au profit de Bulma CSS et du système de composants CheckMaster.

## 1. RÈGLES D'OR
- **Logique PHP intacte** : Conserver toutes les boucles, conditions et variables.
- **Zéro modification externe** : Ne pas toucher aux contrôleurs, modèles ou routes.
- **Suppression Tailwind** : Toutes les classes comme `bg-white`, `p-6`, `flex`, `grid` doivent disparaître.
- **Composants CheckMaster** : Utiliser l'objet `$c` (ComponentHelper) pour générer le HTML structurel.
- **Layouts CM** : Utiliser les layouts `app.php` pour le back-office et `auth.php` pour les pages publiques.

## 2. GUIDE DE CONVERSION VISUELLE (TAILWIND -> BULMA/CM)

| Élément | Tailwind (Ancien) | Bulma / CM (Nouveau) |
| :--- | :--- | :--- |
| Conteneur | `container mx-auto` | `container` ou `section` |
| Grille | `grid grid-cols-N` | `columns is-multiline` |
| Colonne | `col-span-1` | `column is-N` |
| Carte | `bg-white rounded-lg shadow` | `$c->panel('detail-card', [...])` ou `.box` |
| Bouton | `bg-blue-500 text-white` | `button is-primary` |
| Formulaire | `input border-gray-300` | `$c->form('field', [...])` |
| Table | `table-auto w-full` | `$c->table('data-table', [...])` |
| Espacement | `p-4, m-4, mb-6` | Classes Bulma `p-4, m-4, mb-6` (identiques) |

## 3. UTILISATION DU COMPONENT HELPER ($c)
Chaque fichier doit commencer par l'initialisation du helper si nécessaire :
```php
<?php if (!isset($c)) { $c = new ComponentHelper(); } ?>
```

## 4. PLAN DÉTAILLÉ PAR FICHIER

### GROUPE A : DASHBOARD & STATISTIQUES
*Fichiers : dashboard_content.php, dashboard_commission_content.php, dashboard_enseignant_content.php, dashboard_scolarite_content.php, dashboard_secretaire_content.php*

- **Action** : Utiliser le layout `$c->layout('dashboard-page')`.
- **Transformation** : Remplacer les cartes de statistiques par `$c->widget('stat-card', [...])`.
- **Tableaux récents** : Utiliser `$c->table('data-table')` avec l'option `is-striped`.

### GROUPE B : GESTION DES PARAMÈTRES (CRUD)
*Fichiers dans `parametres_generaux/` (19 fichiers) et `parametres_generaux_content.php`*

- **Action** : Refactoriser vers `$c->layout('crud-page')`.
- **Composants clés** :
  - Barre d'outils (Recherche/Ajout) : `$c->table('toolbar', [...])`.
  - Liste : `$c->table('data-table', [...])` avec pagination `$c->table('pagination')`.
  - Formulaires : `$c->form('form-group')` pour chaque champ.

### GROUPE C : GESTION DES ÉTUDIANTS & RH
*Fichiers : gestion_etudiants_content.php, liste_etudiants_content.php, gestion_rh_content.php, dossiers_academiques_content.php*

- **Action** : Supprimer les grilles de liens personnalisées.
- **Transformation** : Utiliser `$c->panel('detail-card')` pour les menus de navigation internes ou Bulma `columns`.
- **Formulaires RH** : Utiliser les composants spécialisés `$c->special('rh-enseignant-form')` ou `$c->special('rh-pers-admin-form')`.

### GROUPE D : SOUTENANCES & CANDIDATURES
*Fichiers : candidature_soutenance_content.php, gestion_candidatures_soutenance_content.php, plannificaiton_soutenance_content.php, Programation_soutenance_content.php*

- **Action** : Utiliser `$c->nav('steps')` pour guider l'utilisateur.
- **Formulaires complexes** : Utiliser `$c->form('select-search')` pour la sélection d'étudiants/projets (autocomplete).
- **Affichage PDF** : Intégrer `$c->special('pdf-viewer')` pour les rapports.

### GROUPE E : RÉCLAMATIONS & FEEDBACK
*Fichiers : gestion_reclamations_content.php, admin_reclamations_content.php, soumettre_reclamation.php*

- **Action** : Utiliser `$c->feedback('alert')` pour les messages de succès/erreur.
- **Suivi** : Timeline Bulma pour l'historique des réclamations.

### GROUPE F : COMPTES RENDUS & PV
*Fichiers : redaction_compte_rendu_content.php, pv_soutenance/annexeX.php, archives_compte_rendu_content.php*

- **Action** : Utiliser `$c->special('rich-editor')` pour la saisie des textes.
- **Aperçu** : Utiliser Bulma `.content` pour l'affichage propre des textes formatés.

## 6. PROCÉDURE DE VALIDATION
Après chaque modification de fichier :
1. Vérifier qu'aucune classe Tailwind ne subsiste (recherche globale `class=".*-[0-9]"`).
2. Vérifier que la structure est cohérente avec Bulma (utilisation de `.columns`, `.column`, `.box`).
3. Vérifier que les helpers `$c` sont correctement appelés avec les bons paramètres.
4. S'assurer que les boutons d'action conservent leurs liens PHP originaux.
