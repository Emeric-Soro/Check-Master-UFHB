RÈGLES TRANSVERSES OBLIGATOIRES (INSTRUCTION.MD)
================================================================================
- Philosophie Backend Only: Toutes les interfaces sont décrites ici pour la logique de comportement backend, mais aucun fichier .php dans /views n'est maintenu.
- Segmentation polarisée: pôle supérieur statique (saisie/validation) + pôle inférieur défilant (liste/historique).
- Triangulation de la donnée: panneau latéral caché par défaut pour le détail, suppression, modification via réinjection.
- Densité sémantique calibrée: champs dimensionnés selon la nature des données, sans surcharge visuelle.
- Philosophie zéro rupture: pas de modal bloquante sauf action destructrice; la modification se fait par retour au pôle supérieur.
- Morphologie adaptative (Backend logic): mobile = navigation en tiroirs (liste/détail); desktop = vue panoramique.
- Année académique active visible en haut à droite sur toutes les pages. (en lecture seule en dehors de l'admin)
- Pour chaque CRUD: formulaire statique en haut, puis barre pagination/recherche/export/import/imprimer, puis tableau avec actions modifier/supprimer/archiver.
- Auto-remplissage obligatoire quand une référence est sélectionnée (étudiant, enseignant, entreprise, inscription, type utilisateur, groupe utilisateur).
- Palette UI obligatoire:
  * `primary: #1a5276` pour la sidebar.
  * `primary-lighter: #3498db` pour le fond global de l'application.
- Boutons/actions: uniquement nuances de bleu ou vert; ne pas utiliser orange/rouge pour des actions.
- Couleurs d'alerte (orange, rouge, vert alerte): réservées aux notifications, statuts et messages.
- Responsive prioritaire: chaque comportement doit être décrit pour desktop/tablette/mobile (Navigation tiroir sur mobile).
- Création utilisateur centralisée: les comptes sont créés dans l'écran Gestion Utilisateurs.
- Pratiquement toutes les pages vont adopter le système Segmentation polarisée (Zone de saisie/validation statique en haut + zone de liste/historique défilante en bas) pour
une expérience utilisateur cohérente et optimisée) sauf les écrans de type "Tableau de bord" qui peuvent adopter une structure plus libre (widgets + graphiques), editeur de texte, ou formulaire de configuration avancée.

2. LISTE EXHAUSTIVE DES PARAMETRAGE
A. Paramètres Applications

[Onglets]Application
app_name : Nom de l'instance (CheckMaster UFRMI)
app_timezone : Fuseau horaire (ex: Africa/Abidjan)
app_locale : Langue du système (fr_FR)
pagination_default : Nombre de lignes par tableau (défaut 25)

[Onglets]Branding
app_logo : Logo principal de l'application
app_favicon : Favicon de l'onglet navigateur
logo_filiere : Logo de l'UFR-MI pour les en-têtes PDF
logo_universite : Logo de l'UFHB pour les documents officiels
logo_mairie : Logo tutelle pour les documents spécifiques

[Onglets]Sécurité
session_timeout : Délai d'inactivité avant déconnexion (minutes)
session_concurrent : Autoriser ou non plusieurs connexions simultanées
password_min_length : Longueur minimale du mot de passe
password_require_uppercase : Exiger au moins une majuscule
password_require_number : Exiger au moins un chiffre
password_require_special : Exiger au moins un caractère spécial
login_max_attempts : Nombre d'échecs avant blocage temporaire
login_lockout_duration : Durée du blocage après échecs (minutes)
csrf_token_lifetime : Durée de vie des jetons de formulaire (secondes)
auth_remember_me_ttl : Sécurité : Durée de validité du cookie "Se souvenir de moi".
auth_password_reset_ttl : Sécurité : Validité du lien de reset (secondes, Défaut 3600).
app.name, `app.base_url`.
mail.enabled, `mail.smtp.host`, `mail.smtp.port`, `mail.smtp.encryption`, `mail.smtp.auth`.
mail.from.email, `mail.from.name`, `mail.reply_to.email`, `mail.bcc_admin.email`.
database.dsn, `database.username`, `database.password`

B. Paramètres Généraux

[Onglets]Commission
COMMISSION_QUORUM : Nb de votes requis pour valider une décision (défaut 4)
DELAI_VOTE_JOURS : Délai limite pour le dépôt d'un avis en commission

[Onglets]Jury
JURY_MEMBRES_REQUIS : Nombre standard de membres pour un jury (défaut 5)
JURY_MEMBRES

[Onglets]Rapport
RAPPORT_MIN_MOTS : Seuil minimal de mots pour autoriser la soumission
STAGE_DUREE_MIN_JOURS : Durée minimale de stage pour validation (ex: 180j)

[Onglets]Notation
NOTE_MAXIMUM : Barème de référence (généralement 20)

DATE_LIMITE_INSCRIPTION : Bloque les nouvelles inscriptions au-delà d'une date par année.
DATE_LIMITE_SOUMISSION_RAPPORT : Paramètre par année académique.

[Onglets]Workflow
VERIF_SCOLARITE_AUTO : Auto-vérification du solde avant soumission rapport
VERIF_SCOLARITE_BLOQUANTE : Si actif, bloque le dépôt si la scolarité n'est pas soldée
DETTE_TOLERANCE_MAX : Scolarité : Montant résiduel autorisé pour être considéré "à jour" (FCFA).
PROMOTION : Masque de saisie des années de promotion.

[Onglets]Délibération
SEUIL_ADMISSION : Note minimale pour être admis (défaut 10.0)
ARRONDI_DECIMALES : Nombre de décimales pour les moyennes finales
Table formule_calcul : Formules (Annexe 2, Annexe 3) pour calcul final

[Onglets]Frais de Scolarité : Tarifs par défaut par niveau (M1/M2).
[Onglets]Niveaux (M1-M2) : Codes, libellés et frais par défaut associés.
[Onglets]Semestres : Organisation temporelle des parcours.
