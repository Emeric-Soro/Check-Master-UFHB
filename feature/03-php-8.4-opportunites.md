# Opportunités avec PHP 8.4+ (plateforme configurée)

## Sécurisation et robustesse
- **Enums pour les statuts/roles** : remplacer les chaînes (`statut_utilisateur`, `lib_role`, `lib_GU`) par des `enum` (`Actif`, `Inactif`, `Suspendu`, rôles jury) pour éviter les fautes de frappe et typer les retours des modèles.
- **Constantes typées (>=8.3)** : déclarer des constantes typées dans les classes de configuration et les repositories (`class UtilisateurRepository { public const string STATUT_ACTIF = 'Actif'; }`) pour fiabiliser les comparaisons.
- **`#[\SensitiveParameter]`** sur les mots de passe/jetons (`AuthController::login`, `updatePassword`) afin d’éviter la fuite de secrets dans les traces et dumps.
- **`json_validate()`** (8.3) pour vérifier les charges utiles importées (Excel -> JSON, APIs futures) avant décodage dans `ExcelImportService`.

## Architecture et lisibilité
- **Classes `readonly` (>=8.2)** pour les DTO/config (credentials SMTP/DB, objets de résultat dans `EvaluationSoutenanceController`) afin de garantir l’immuabilité une fois construits.
- **`match` expressions** pour remplacer les séries de `if/else` dans le routage des menus ou le mapping des décisions d’évaluation, rendant les branches exhaustives.
- **Nullsafe operator + typed properties** pour réduire les `isset` et harmoniser les signatures des modèles (ex. `?Enseignant` retourné par `getEnseignantByLogin`).
- **`#[\Override]` (8.3)** sur les classes qui redéfinissent des méthodes héritées (ex. futurs services ou contrôleurs de base) pour sécuriser les refactors.

## Performance et DX
- **Random\Randomizer** pour générer des tokens CSRF/OTP plus sûrs et injectables (remplace `mt_rand`/`uniqid` s’ils sont utilisés).
- **Fibres/async I/O** (disponibles depuis 8.1) exploitables via des bibliothèques compatibles pour paralléliser des envois d’e-mails ou des exports sans bloquer la requête principale.
- **Génération de PDF/Word en tâches asynchrones** : combiner `Symfony Process` ou une queue avec les nouvelles features de typage strict pour fiabiliser les workers.

## Actions concrètes
- Introduire des `enum` pour les statuts (`utilisateur`, `candidature`, `jury`) et les injecter dans les modèles au lieu de chaînes magiques.
- Créer des classes `readonly` `DatabaseConfig` et `MailConfig` construites via variables d’environnement, puis injectées dans `Database` et `EmailService`.
- Annoter les paramètres sensibles (`#[\SensitiveParameter] $password`) et typer les retours des méthodes de modèles/contrôleurs.
- Valider systématiquement les données importées avec `json_validate()` et des objets valeur (`readonly`) avant insertion en base.
